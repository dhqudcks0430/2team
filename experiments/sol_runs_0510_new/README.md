# 범용 AI 셔틀 설계 실험 run-05 ~ run-10 new (gpt-6.2-sol, 시간 보조지표 v2)

[`../sol_runs_0510`](../sol_runs_0510/README.md)과 같은 과제를 새 PROMPT.md로 다시 6회 돌린 제출물입니다.

## 이전 실험과 다른 점

- PROMPT.md에 **시간 보조지표(v2): 0~90분 평균 누적 수요충족률**이 추가됐습니다.
  - 점수(%) = 100 × Σ max(0, 5400 − T) / (5400 × 16230). T는 출발부터 최종 목적지 도착까지 걸린 시간(초)입니다.
  - 주지표(90분 내 도착 인원)를 우선하고, 두 목표 사이의 선택을 메모에 한 줄로 적도록 했습니다.
- 프롬프트는 각 회차 `시작문장.md`의 문장을 그대로 넣었습니다. 여기에 덧붙인 것은 세 가지입니다.
  - 작업 디렉터리 지정
  - 그 폴더 밖·이전 실험·저장소·웹 접근 금지
  - 완료 보고 형식

## 조건

- 모델: Codex `gpt-6.2-sol`, reasoning effort `high`. 회차마다 새 세션 하나를 썼습니다(Orca 워커, 2026-11-18).
- 차량: 11대(45인승). 수요: 16,230명.
- 입력 CSV 4개는 `../sol_runs_0510/inputs/`와 같습니다(바이트 일치). 그래서 다시 넣지 않았습니다.

두 지표 사이의 선택(각 `sol-run-XX.md` 메모 요약):

| run | 선택 |
|---|---|
| run-05 | 천왕 연결이 누적 충족률에 유리했지만, 90분 내 도착 인원이 더 많은 구로디지털단지 연결을 택함 |
| run-06 | 신도림행이 누적 충족률에 유리했지만, 90분 내 도착 인원이 더 많은 천왕행을 택함 |
| run-07 | 도착 인원이 비슷한 후보끼리는 회차·환승 보행이 짧은 쪽을 택해 누적 충족률을 챙김 |
| run-08 | 더 짧은 구로역행 후보 대신, 신도림동 승차 정류장 두 곳을 잇는 구로역행으로 90분 내 도착을 우선함 |
| run-09 | 시간이 더 들어도 개봉중앙시장을 경유해 90분 내 도착 가능 승객을 넓힘 |
| run-10 | 개봉 남부는 중앙시장 정차로 범위를 넓히고, 온수 북부는 중간 정차 없이 바로 연결함 |

- 이번에도 6회 모두 11개 노선에 1대씩 배분했습니다.
- 이전 실험과 비교하면 노선이 2–3개 정류장으로 모였습니다.
- 사용 정류장 수의 차이도 이전 22–36개에서 25–29개로 줄었습니다.
